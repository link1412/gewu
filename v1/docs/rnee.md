# 折射光连接(RNEE):釉里的点直接连到灯

pbrt-v4 打的补丁(`patches/pbrt-v4-gewu.patch`)。S1 写并验证。

## 为什么要它

- 釉是一层散射介质,外面包着一个光滑的界面(玻璃态的釉面)。
- 釉里的点要被灯照到,光必须先折射进来。pbrt 的 `SampleLd()` 往灯打的影子射线碰到釉面就停,所以釉里的点等于没有直接光。只剩路径追踪碰巧从釉面折射出去、又正好打到灯,噪声极大。
- S1 实测(480×320,釉板 + 三道裂):
  - volpath 1024 spp 噪声 35%;
  - bdpt 256 spp 噪声 49%;
  - 把介质换成灰的、平的都没用,换成「帐篷光」(大面积)才降到 17.6%。
  - 结论:是「透过光滑界面找灯」这件稀有事件造成的,不是光谱也不是介质。

## 做法

- **界面**:`Material "dielectric" ... "bool refractivenee" true`。
  - 反射走微表面(`roughness` 只模糊反射,保留釉面的「酥油光」),透射当光滑的算(delta)。两者用宏观法线上的菲涅耳来选。
  - 釉里散射很强,透射那一点模糊看不出来;反射的模糊看得出来。
  - 要求 `eta` 是常数(连接只为一个折射率求解),不是就报错。
- **积分器**:`Integrator "volpath" "bool refractivenee" true` 打开连接;不开就是普通的路径追踪,同样的界面(这就是对照组)。
- **连接**(在每个非镜面的顶点 x:介质散射点、釉下的胎面):
  1. 在面光源上采一点 z。
  2. 解 x→y→z 的折射点 y(`SolveRefraction()`)。
     - 先找一个起点:沿「引导方向」(路径上一次碰到的表面的法线,指向界面薄的一侧)找到釉面;找不到就沿 x→z 的直线。
     - 在 y 的切平面上解斯涅尔定律:一元方程,单调,牛顿法加区间保护。
     - 再从 x 往解出来的点打一条探测射线,落回真实的釉面。
     - 重复,直到不动为止,最多 16 步。每步的欠校正大约是 (深度/曲率半径)(1 − cosθ_z/(η cosθ_x)):花瓶的壁一步就到,1.5 mm 的口沿每步缩 0.4。
     - x→y 的方向用解出来的角度构造,不用两个点相减:x 常常就在釉面下面一点点,相减会丢精度。
     - 最后在 y 的法线上验一遍斯涅尔定律(误差 1e-3)。
  3. 估计值 = f(x)·|cos|·T_F(y)·(η_x/η_z)²·Le(z→y)·透射率 ÷ (p(z)/J)。
     - J = dω_x/dA_z,用重新追踪的方向做差分:偏 h = 3e-4 rad,走过真实的釉面(着色法线、凹凸都算),落到灯在 z 的切平面上。
     - 每个方向先试 +h、不行再试 −h,所以靠近临界角的连接会往远离全反射的那边偏。
     - 两边都不行(连接正好在界面的边上)才退回切平面的解析式;那种情况要计数,目前从没发生过。
  4. x→y 之间的薄介质(裂缝)让光直着过去,只按它的透射率衰减。y→z 和 `SampleLd()` 一样,碰到任何材质就挡住。
- **为什么不能用切平面的解析 J**:曲面会聚光。数值检验(S1):
  - 平面:解析式、射线微分、有限差分三者一致到 1e-6;
  - 曲率半径 20 mm、深 1.2 mm:解析式偏低 4–5%;
  - 曲率半径 5 mm、深 1 mm:偏低 13–16%。
  - 这是真实的透镜效应,凹凸(橘皮)也有。射线微分用 pbrt 的 dndu/dndv 能算准曲率,但解析形体反向时 dndu 的符号不可靠,凹凸贴图的曲率它也不知道。所以用重新追踪做差分。
- **和路径追踪不重复计算**:
  - 路径追踪也会走同样的路(非镜面的 x → 若干裂缝透射 → 在釉面折射出去 → 打到灯)。Li() 用 `rneeState` 跟踪这种路径。
  - 打到灯时,只有在「从 x 出发的求解器能找到同一个折射点、并且能采到这个灯点」的情况下,才丢掉这次的发光(连接已经算过了)。
  - 求解器找不到的解(边角上的第二个解、远处的解),留给路径追踪。所以不丢光、不重复算。
- **为什么不用 MIS**:
  - S1 试过 MIS(balance heuristic)。路径那边每次都要再算一遍 J,釉板上慢了 48%,噪声却一样(15.4% 对 15.7%)。
  - 第一版只按状态划分、不验证求解器:平板上无偏,圆柱上偏低 1.2%,偏差集中在圆柱上部。我的解释:求解器从直线起步,在圆柱顶上找到了盖子上的解,漏了侧面上的解。验证求解器之后就无偏了。
- **限制**:
  - 只连面光源;环境光留给路径追踪。
  - 球形面光源会报错:它的采样只覆盖朝着 x 的那半个球冠,连接需要整个灯都能采到。
  - 一次只过一个折射界面。BSSRDF 材质不连。

- S3 修正:连接穿过薄介质时,拿去算余弦的方向是 `SpawnRayTo` 的方向,不是单位长;现在先归一化。以前的裂缝(eta ≠ 1、不吸收)受的影响小,修后 `tests/rnee` 和 S1 的表一样(釉板 1.0005,rms z 1.03;圆柱 1.0016,1.07);带吸收的薄膜(`docs/coats.md`)才看出来。
- S3 修正:x 离 y 比 y 的舍入误差还近时(光学层的瓶,x 在釉面下 0.37 µm,坐标约 1500 mm),`SpawnRayTo(y)` 的方向是零,三角形求交得 t = NaN,pbrt 的检查让整个渲染崩溃。现在零方向就当 x 和 y 之间什么也没有(pbrt 自己的 `SampleLd()` 也这样)。别的路径一位不变:`tests/rnee` 的 on1/on2(釉板、圆柱)修前修后逐位相同;崩溃的场景(`out/optics/rnee-crash/`)整张渲完。

## 验证(S1,`tests/rnee/`)

步骤(在 out/ 下的一个空目录里做):

```
python3 -I tests/rnee/scenes.py slab ref1:240:160:4096:1:false ref2:240:160:4096:2:false \
    on1:240:160:256:1:true on2:240:160:256:2:true off1:240:160:256:1:false off2:240:160:256:2:false
# ref*/off* 放多核机器上跑,on* 都行
python3 -I tests/rnee/compare.py ref1.pfm ref2.pfm on1.pfm on2.pfm 8
```

- 圆柱的场景把 `slab` 换成 `cylinder`,`compare.py` 的块大小用 4 和 8。
- `compare.py` 输出四项:
  - 整图均值比;
  - 每个块的 z 值,用两个种子的差估误差;
  - 相对差的分布;
  - 逐像素的相对噪声。

结果(240×160):

| 场景 | 方法 | spp | 时间 | 逐像素噪声 | 均值 / 参考 | 块 z(均值,rms) |
|---|---|---|---|---|---|---|
| 釉板 + 3 裂 | 路径追踪 | 2×4096 | 80 s(多核机器) | 13.5% | 参考 | |
| | 路径追踪 | 256 | 7.1 s | 53.7% | 1.0018 | −0.02, 1.02 |
| | RNEE | 256 | 12.4 s | 15.7% | 1.0006 | +0.00, 1.03 |
| 圆柱 R5 + 1 裂 | 路径追踪 | 2×4096 | 24 s(多核机器) | 9.8% | 参考 | |
| | 路径追踪 | 256 | 2.6 s | 35.3% | 1.0028 | −0.10, 1.14 |
| | RNEE | 256 | 3.9 s | 24.1% | 1.0017 | −0.06, 1.07 |

- **无偏**:
  - 均值和参考之差在两个种子之间的差以内;
  - 块的 z 值和纯噪声一样(16×16、32×32 的块没有一个超过 3σ);
  - z 图上没有任何空间结构(裂缝、边、顶上都没有)。
  - 8×8 块里偶尔有 |z|≈4 的,是路径追踪噪声的长尾,对照组(路径追踪对路径追踪)也有。
- **效率**(1/(方差×时间)):
  - 釉板 6.7 倍;
  - 圆柱 1.4 倍。圆柱有一半的面上灯在当地的地平线以下,那里没有一次折射能到的光,光是在釉里绕过来的,连接帮不上。
- **剩下的噪声**:主要在裂缝上:x → 裂缝全反射 → 釉面折射 → 灯。连接只过一个折射,不过镜面反射。以后要是裂缝上的亮线收敛太慢,再考虑。
- 速度:每个连接大约 7–10 条射线(起点 1、迭代 1–3、差分 3、透射 2)。
